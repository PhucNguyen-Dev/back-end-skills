# x402 — pay-per-request over HTTP

x402 revives HTTP status `402 Payment Required`. Governed by the x402
Foundation under the Linux Foundation; Python SDK at `x402-foundation/x402`.

## Install

```bash
pip install "x402[fastapi,httpx,evm]"   # FastAPI server + httpx client + EVM
pip install "x402[fastapi,httpx,evm,svm]"  # add Solana
```

Extras: `fastapi` | `flask` (server), `httpx` | `requests` (client), `evm` |
`svm` (chains). Pairings: FastAPI→httpx, Flask→requests.

## Protocol flow

```
Client                         Resource server              Facilitator
  |-- GET /resource -------------->|                            |
  |<-- 402 PAYMENT-REQUIRED -------|  (amount, asset, network,   |
  |                                |   payTo, scheme)            |
  |  signs payment locally         |                            |
  |-- GET /resource + PAYMENT-SIGNATURE ------------------------|
  |                                |-- POST /verify ----------->|
  |                                |<-- valid ------------------|
  |                                |-- POST /settle ----------->|
  |                                |<-- tx_hash ----------------|
  |<-- 200 OK + PAYMENT-RESPONSE --|                            |
```

Headers (v2): `PAYMENT-REQUIRED` (challenge), `PAYMENT-SIGNATURE` (signed
payload, base64url JSON), `PAYMENT-RESPONSE` (settlement receipt). v2 uses
CAIP identifiers for networks/assets (e.g. `eip155:84532` = Base Sepolia,
`eip155:8453` = Base mainnet, `solana:…` mainnet/devnet IDs).

## Seller (resource server)

```python
from x402.http import FacilitatorConfig, HTTPFacilitatorClient, PaymentOption
from x402.http.middleware.fastapi import PaymentMiddlewareASGI, set_settlement_overrides
from x402.http.types import RouteConfig
from x402.mechanisms.evm.exact import ExactEvmServerScheme
from x402.server import x402ResourceServer

facilitator = HTTPFacilitatorClient(FacilitatorConfig(url="https://x402.org/facilitator"))
server = x402ResourceServer(facilitator)
server.register("eip155:84532", ExactEvmServerScheme())      # Base Sepolia
server.register("solana:EtWTRABZaYq6iMfeYKouRu166VU2xqa1", ExactSvmServerScheme())  # Solana devnet

routes = {
    "GET /api/generate": RouteConfig(
        accepts=[PaymentOption(scheme="exact", pay_to="0x…", price="$0.001",
                               network="eip155:84532")],
        mime_type="application/json",
        description="AI completion",
    ),
}
app.add_middleware(PaymentMiddlewareASGI, routes=routes, server=server)
```

- `price` accepts `"$0.001"` shorthand or an `AssetAmount` for explicit
  contract/version (USDC `0x036CbD53842c5426634e7929541eC2318f3dCF7e` on
  Base Sepolia).
- Wildcard routes: `"GET /premium/*"`.
- Facilitators: `https://x402.org/facilitator` (testnets), Coinbase CDP
  `https://api.cdp.coinbase.com/platform/v2/x402`, PayAI
  `https://facilitator.payai.network` (auth via Ed25519 JWT for paid tiers).

### Variable pricing (`upto`)

For AI work where the cost is known only after execution: the client
authorizes a **maximum**, you settle the **actual**.

```python
from x402.mechanisms.evm.upto import UptoEvmServerScheme
from x402.http.middleware.fastapi import set_settlement_overrides

server.register("eip155:84532", UptoEvmServerScheme())

routes = {"GET /api/generate": RouteConfig(
    accepts=[PaymentOption(scheme="upto", pay_to="0x…", price="$0.10",
                           network="eip155:84532")],  # $0.10 = authorized max
    mime_type="application/json", description="LLM call, metered")}

@app.get("/api/generate")
def generate(response: Response):
    actual_atomic = compute_cost()          # in 6-decimal USDC atomic units
    set_settlement_overrides(response, {"amount": str(actual_atomic)})
    return {"result": "...", "chargedAtomic": str(actual_atomic)}
```

The client is never charged more than the authorized max.

### Schemes worth knowing

| Scheme | Use |
| --- | --- |
| `exact` | Fixed price per request; settle now |
| `upto` | Metered: authorize max, settle actual ≤ max |
| `auth-capture` | Hold, partially capture, or refund later |
| `batch-settlement` | Signed commitment grants access now; value settles later (high-frequency sessions) |

Replay protection is core: 32-byte nonces + validity windows
(`validAfter`/`validBefore`). Wallet-proof and signed receipts ship as
extensions (`sign-in-with-x`, `offer-and-receipt`).

The client wrapper: parse 402 → build payload → sign → retry with

## Facilitator (run your own)

```python
from x402 import x402Facilitator
from x402.mechanisms.evm.exact import ExactEvmFacilitatorScheme

facilitator = x402Facilitator()
facilitator.register(["eip155:8453", "eip155:84532"],
                     ExactEvmFacilitatorScheme(wallet=wallet))
result = await facilitator.verify(payload, requirements)
if result.is_valid:
    settle = await facilitator.settle(payload, requirements)
```

`verify` checks the signature/authorization; `settle` submits the on-chain
transfer. Your server needs no chain connectivity if you call a hosted
facilitator instead.

## Seller checklist

- [ ] Price stated in the 402 before any billable work
- [ ] `pay_to` address correct per network; test on Base Sepolia first
- [ ] Facilitator chosen deliberately for mainnet (trust, uptime, fees)
- [ ] Settlement receipts stored for reconciliation
- [ ] Every accepted payment also logged against your metering pipeline
      (see `ai-metering-billing` skill)
- [ ] Spend authority verified upstream (AP2 or your own policy — see
      `agent-wallet-spend-policy` skill)
